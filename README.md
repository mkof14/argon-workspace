# AGRON Workspace

Единый операционный кабинет AGRON Inc. Все отделы, сотрудники, партнёры и поставщики работают в одном месте. Каждый видит только свои разделы.

**Стек:** Next.js 14 на Vercel, Supabase (база данных, вход, права доступа), Anthropic API (ИИ-ассистент).

- **Языки:** English, Русский, Українська, العربية (интерфейс переворачивается справа налево).
- **Тема:** светлая или тёмная, переключается одной иконкой.

В каждом разделе есть:
- таблица и доска (канбан с перетаскиванием);
- поиск и фильтр по статусу;
- карточка записи с комментариями и историей изменений;
- кнопки Copy, Print, PDF, Share, Download и экспорт в CSV;
- кнопка «Спросить ИИ».

**Встроенные правила AGRON:**
- **Сделка → Won** только после санкционной проверки и проверки конечного пользователя со статусом **Cleared**.
- **Контейнер → Shipping** только после экспортной проверки со статусом **Cleared**.
- **Записи «Контролируемые технические данные»** видят только сотрудники с отметкой *US person*. Защита на уровне базы данных, а не только интерфейса.
- **Партнёры, поставщики и инвесторы** видят только записи своей компании или открытые всем внешним (`*`). Изменять ничего не могут.

Обновление базы: выполните `supabase/update-v2.sql`, затем `supabase/access.sql`.

## 2. Демо за 1 минуту (без настройки)

```bash
npm install
npm run dev
```
Откройте http://localhost:3000. Без переменных Supabase приложение работает в демо-режиме:
- пример данных хранится в браузере;
- внизу меню есть переключатель «Смотреть как» (Владелец, Инженер, Операции, Финансы, Продажи, Партнёр, Поставщик). Так видно, кто что видит.

Записи с пометкой **Sample** — примеры. Реальные данные AGRON уже загружены: матрица комплаенса, ключевые вопросы, регуляторы, юрлица и товарные знаки.

## 3. Запуск в работу

### Supabase
1. Создайте проект на supabase.com. Регион для данных ОАЭ согласуйте с юристом (UAE PDPL).
2. Откройте **SQL Editor** и выполните по очереди:
   1. `supabase/schema.sql`
   2. `supabase/access.sql`
   3. `supabase/seed.sql`
3. В разделе **Authentication → Providers** включите:
   - **Email** — вход по ссылке на почту;
   - **Azure** — вход через Microsoft 365;
   - при желании **Google**.
4. В разделе **Authentication → URL Configuration** укажите адрес сайта: `https://workspace.agron1.com`.

### Anthropic
Создайте один ключ API для всей компании на console.anthropic.com. Задайте месячный лимит расходов прямо в консоли.

### Vercel
1. Загрузите проект в GitHub (приватный репозиторий) и импортируйте его в Vercel.
2. В разделе **Settings → Environment Variables** заполните переменные из `.env.example`.
3. Подключите домен `workspace.agron1.com`.
4. Первый, кто войдёт, автоматически становится **Владельцем**. Остальных приглашайте через **Администрирование → Пользователи и роли**: укажите роль, компанию, отметку US person и лимит ИИ.

## 4. Как добавить раздел или поле

Вся структура описана в одном файле: `src/config/workspace.config.mjs`.
1. Добавьте отдел, раздел или поле. Названия задаются на 4 языках.
2. Выполните `npm run gen:access`.
3. Запустите заново полученный `supabase/access.sql` в SQL Editor.

Программировать экраны не нужно: таблица, доска, форма и права строятся автоматически.

## 5. Как держать расходы под контролем

- **Вход без Claude.** Сотрудникам и партнёрам аккаунт Claude не нужен: они входят через Microsoft, Google или по ссылке на почту.
- **Один ключ API.** Компания платит только за реальные запросы к ИИ.
- **Режим «Быстро» по умолчанию** (быстрая и дешёвая модель): сводки, переводы, черновики. Режим «Глубоко» включается вручную для юридического, технического и финансового анализа. Юридический раздел открывается сразу в режиме «Глубоко».
- **Кэширование.** Постоянная часть инструкций кэшируется, поэтому повторные вопросы дешевле.
- **Личный лимит.** У каждого пользователя месячный лимит токенов. Администратор меняет его в таблице пользователей, а при исчерпании запросы останавливаются.
- **Файлы** храните в SharePoint или OneDrive, а в Workspace держите ссылки. Так база Supabase остаётся маленькой и дешёвой.

## 6. Важно: экспортный контроль

Vercel и Supabase — обычные коммерческие облака. **Не храните здесь технические данные под ITAR.** Отметка «Контролируемые» защищает только от доступа не-US persons внутри системы. Для данных уровня ITAR нужна отдельная среда, например Microsoft 365 GCC High. Решение принимается вместе с экспортным юристом.
